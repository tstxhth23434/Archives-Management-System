## 四、业务规则（答辩可讲）

| 规则 | 实现 |
|---|---|
| 全宗号唯一 | 新增/编辑时 Service 层校验 + 数据库唯一索引兜底 |

## 四.5、代码审查修复（2026-08-18 review 发现）

**Bug：逻辑删除 + 唯一索引冲突**
- 现象：全宗/门类逻辑删除（del_flag=1）后，记录仍在表中，而唯一索引（fonds_code / fonds_id+type_code）不含 del_flag → **删除后重建同 code 抛 DuplicateKeyException（系统异常）**
- 修复：Mapper 新增 `countByCodeIncludingDeleted` / `countByTypeCodeIncludingDeleted`（原生 SQL 覆盖已删记录），Service 唯一校验改调新方法
- **业务约定：全宗号/门类代码不复用**（校验覆盖已删除记录）
- 验证：删除→重建同 code → 返回业务提示"已存在"（全宗/门类均通过）

**前端隐藏耦合**：门类页 `fetchFonds()` 加 try-catch，无 `archive:fonds:query` 权限时下拉为空、不影响列表加载。
