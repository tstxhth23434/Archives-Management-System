## 二、接口说明

| 接口 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 登录 | POST | `/api/auth/login` | 参数 `{username, password}`，返回 token + 用户信息 |
| 登出 | POST | `/api/auth/logout` | 需带 Authorization 头 |
| 当前用户 | GET | `/api/auth/info` | 需带 Authorization 头 |
| 修改密码 | POST | `/api/auth/change-password` | 参数 `{oldPassword, newPassword}`，成功后强制下线重新登录 |

## 三、密码格式规则（正则校验）

- **规则**：8-16 位，必须同时包含字母和数字，仅允许字母/数字字符，禁止特殊字符
- **正则**：`^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d]{8,16}$`
- **实现**：`PasswordConstants.PASSWORD_REGEX` + `@Pattern` 注解，非法格式由全局校验统一返回 400
- **设计决策**：
  - 旧密码不校验格式（历史密码可能不符合新规则，校验会导致无法改密码）
  - 登录接口不校验格式（防暴露密码规则；防历史弱密码账号被锁死无法登录）
  - 格式校验只作用于"设置新密码"场景（改密码、后续建用户）

## 四、测试结果（冒烟测试全部通过）

### 登录 / 认证

| 用例 | 结果 |
|---|---|
| 正确密码登录 | ✅ 200，返回 token |
| 带 token 获取用户信息 | ✅ 200，用户信息完整 |
| 错误密码登录 | ✅ 500 "用户名或密码错误" |
| 空参数登录 | ✅ 400 参数校验提示 |
| 无 token 访问受保护接口 | ✅ 401 "未登录或登录已过期" |
| 登出后再访问 | ✅ 401 |

### 修改密码流程

| 用例 | 结果 |
|---|---|
| 正确改密码（admin123 → test123456） | ✅ 200 "修改成功，请重新登录" |
| 旧 token 再访问 | ✅ 401（强制下线生效） |
| 旧密码登录 | ✅ 失败 "用户名或密码错误" |
| 新密码登录 | ✅ 200，返回新 token |
| 原密码错误 | ✅ 500 "原密码错误" |
| 新密码过短（3 位） | ✅ 400 校验提示 |

### 密码格式正则

| 新密码 | 结果 |
|---|---|
| `abc12345`（合法） | ✅ 200 修改成功 |
| `12345678`（纯数字） | ❌ 400 格式提示 |
| `abcdefgh`（纯字母） | ❌ 400 格式提示 |
| `abc123`（仅 6 位，过短） | ❌ 400 格式提示 |
| 17 位（超长） | ❌ 400 格式提示 |

## 五、使用说明

1. 执行 `doc/database/DocumentManagementSystemApplication.sql` 建库建表（已执行）
2. 执行 `doc/database/init_data.sql` 初始化数据（已执行）
3. 启动应用，访问 http://localhost:8080/doc.html
4. 登录接口参数：`admin / admin123`

## 六、注意事项

- 登录失败统一提示"用户名或密码错误"，不区分用户不存在/密码错误（防账号枚举）
- 账号 status=0 时拒绝登录
- 改密码成功后强制下线，旧 token 立即失效，需用新密码重新登录
- 密码格式规则在 `common/constant/PasswordConstants.java`，D4 建用户/重置密码时复用
- 前端依赖 401 跳转登录页，axios 拦截器需处理
